# Omarchy Brave Polish (companion MV3 extension)

Dynamically matches **Brave-Origin** to the active Omarchy system theme —
the same treatment Zen Browser gets, adapted for Chromium constraints.

## What it does

- **Browser chrome (toolbar, tabs, frame, bookmarks)**: full Chromium `theme`
  in `manifest.json`, generated from the Omarchy palette
  (`~/.config/omarchy/themed/brave-manifest.json.tpl`). Toolbar = background,
  frame = darker background, active tab text = foreground, accents = accent.
- **New TabPage (`ntp.html`)**: transparent canvas + glass clock, search,
  and top-sites, themed via `ntp.css` (compiled from
  `~/.config/omarchy/themed/brave-ntp.css.tpl`). Hyprland wallpaper blur
  bleeds through on empty tabs (terminal-style glass); loaded websites stay
  solid. Re-read on every new tab → hot-applies, no restart.
- **NTP delivery without override**: the extension deliberately declares NO
  `chrome_url_overrides` — Brave-Origin brands every extension-provided NTP
  with an unremovable `NewTabFooterWebView` attribution bar (proven: absent
  in Private windows, present for both override and policy delivery of
  extension pages). Instead, the `NewTabPageLocation` managed policy points
  new tabs straight at the plain `file://` page, which carries no
  attribution. `ntp.js` runs API-free there (curated tiles, no detector);
  `ntp.css` still re-reads per load so themes hot-apply. See Setup.
- **Auto-reload on theme change**: `ntp.js` re-reads `theme.json` from disk on
  every new tab; when it differs from the cached copy it calls
  `chrome.runtime.reload()` once, so the new manifest theme applies. Open one
  new tab after `omarchy theme set` and the whole browser re-themes.
- **Site polish (`loader.js`)**: runs at `document_start` on YouTube, GitHub,
  Reddit only. Re-fetches `polish.css` (compiled from
  `~/.config/omarchy/themed/brave-polish.css.tpl`) from disk per navigation
  and injects it inline → hot-applies on next navigation/reload.
- **Universal base (`global.js`)**: runs on ALL websites. Injects `global.css`
  (from `~/.config/omarchy/themed/brave-global.css.tpl`): theme `color-scheme`,
  Omarchy page background, selection, scrollbars, focus rings. Conservative by
  design — pages keep their own painted backgrounds.
- **Full-page recolor**: owned by the Dark Reader fork at
  `~/.config/omarchy/brave-darkreader/` (the Zen treatment, ported). The old
  per-site `loader.js`/`polish.css` layer is retired to avoid double
  recoloring; files remain as fallback reference.
- **Toolbar color**: stock Omarchy `chromium.theme` policy
  (`omarchy-theme-set-browser`). This extension does not touch it.
- **Dark Reader**: intentionally untouched. It remains the tool for full
  arbitrary-page recoloring; this extension handles Omarchy palette matching.

## Files (static vs generated)

Static (edit freely): `manifest.json`, `ntp.html`, `ntp.js`, `loader.js`,
`global.js`, `background.js`.

Generated by `omarchy-sync-brave --sync` (do not hand-edit):
`ntp.css`, `polish.css`, `global.css`, `theme.json`, `manifest.json`.

NOTE: `manifest.json` is generated (theme colors + permissions live there).
Any manifest change requires one manual reload on `brave://extensions`
(Chromium never hot-applies manifest edits). CSS/JS/HTML edits apply on next
tab/navigation with no reload.

## One-time setup

1. Open `brave://extensions`, enable **Developer mode**.
2. **Load unpacked** → `~/.config/omarchy/brave-polish` (kept for the
   toolbar/global polish; NTP no longer needs it).
3. Point new tabs at the plain file page (one root command):
   `sudo install -d -m 0755 -o root -g root /etc/brave/policies /etc/brave/policies/managed && echo '{"NewTabPageLocation": "file:///home/soham/.config/omarchy/brave-polish/ntp.html"}' | sudo tee /etc/brave/policies/managed/omarchy-ntp.json`
4. Fully quit Brave (no lingering `brave` process) and reopen. New tabs load
   the Omarchy page with no footer. Every future `omarchy theme set <name>`
   applies automatically via the `brave-sync.sh` theme-set hook.

## Why not patch Dark Reader / Preferences?

Chromium verifies installed extensions against `Secure Preferences`
checksums — hand-editing install records gets the extension disabled.
Updating *files inside* an already-loaded unpacked extension is safe and
re-read per navigation, which is exactly what this design relies on.
